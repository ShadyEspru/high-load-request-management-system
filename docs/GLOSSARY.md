# قائمة المصطلحات والاختصارات

| المصطلح | الاختصار | التعريف المعتمد في المشروع |
|---|---|---|
| نظام إدارة الطلبات عالية الحمل | HLRMS | المنصة الرئيسية التي تستقبل الطلبات وتوجهها وتتابع تنفيذها |
| طلب | Request | وحدة عمل يرسلها نظام خارجي لمعالجتها |
| حمولة الطلب | Payload | البيانات الخاصة بالمهمة داخل الطلب |
| معرّف الطلب | Request ID | معرّف فريد ينشئه النظام لتتبع الطلب |
| معرّف الارتباط | Correlation ID | معرّف يربط سجلات وخطوات الطلب عبر الخدمات |
| مفتاح منع التكرار | Idempotency Key | قيمة تمنع تكرار الأثر عند إعادة إرسال الطلب نفسه |
| وسيط الرسائل | Message Broker | نظام ينقل الرسائل بين المنتجين والمستهلكين |
| المنتج | Producer | مكون ينشر رسالة إلى RabbitMQ |
| المستهلك | Consumer | مكون يستقبل الرسائل من Queue |
| وحدة التنفيذ | Worker | عملية أو خدمة تنفذ الطلبات المسحوبة من الطابور |
| مجموعة وحدات التنفيذ | Worker Pool | عدة Workers من النوع نفسه تعمل بالتوازي |
| الطابور | Queue | مخزن مرتب للرسائل المنتظرة للمعالجة |
| المبادل | Exchange | مكون RabbitMQ الذي يوجه الرسائل إلى الطوابير |
| مفتاح التوجيه | Routing Key | قيمة تُستخدم لتحديد مسار الرسالة |
| الربط | Binding | قاعدة تربط Exchange بـQueue |
| تأكيد المستهلك | ACK | إشعار بنجاح معالجة الرسالة وحذفها من الطابور |
| رفض الرسالة | NACK | إشعار بفشل المعالجة مع إمكانية الإعادة أو التحويل |
| إعادة المحاولة | Retry | إعادة تنفيذ طلب فشل بسبب خطأ مؤقت |
| التراجع الزمني | Backoff | زيادة مدة الانتظار بين محاولات التنفيذ |
| طابور الرسائل الميتة | DLQ | طابور يستقبل الرسائل التي استنفدت محاولاتها أو رُفضت |
| مبادل الرسائل الميتة | DLX | Exchange يوجه الرسائل الفاشلة إلى DLQ |
| الجلب المسبق | Prefetch | عدد الرسائل غير المؤكدة المسموح بإرسالها لكل Consumer |
| المعالجة غير المتزامنة | Asynchronous Processing | قبول الطلب أولًا وتنفيذه لاحقًا دون إبقاء العميل منتظرًا |
| معدل المعالجة | Throughput | عدد الطلبات المنجزة خلال وحدة زمن |
| زمن الاستجابة | Response Time | الزمن بين إرسال الطلب واستلام الرد |
| زمن الانتظار | Queue Wait Time | الزمن بين دخول الرسالة للطابور وبدء تنفيذها |
| زمن التنفيذ | Processing Time | الزمن الذي يستغرقه Worker لتنفيذ المهمة |
| الاختناق | Bottleneck | مكون يحد قدرة النظام الكلية |
| التوسع الأفقي | Horizontal Scaling | زيادة السعة بإضافة نسخ جديدة من الخدمة أو Worker |
| موازن الحمل | Load Balancer | يوزع الاتصالات على نسخ متعددة من الخدمة |
| تحديد المعدل | Rate Limiting | تقييد عدد الطلبات المسموح بها خلال مدة معينة |
| التتبع الموزع | Distributed Tracing | تتبع رحلة الطلب عبر مكونات متعددة |
| قابلية المراقبة | Observability | فهم حالة النظام من المقاييس والسجلات والتتبع |
| اختبار الحمل | Load Test | اختبار النظام تحت حمل متوقع ومتدرج |
| اختبار الضغط | Stress Test | رفع الحمل حتى تجاوز الحدود الطبيعية |
| اختبار الارتفاع المفاجئ | Spike Test | إرسال زيادة كبيرة ومفاجئة في الطلبات |
| التوفر العالي | High Availability | استمرار الخدمة رغم تعطل بعض المكونات |
| استعادة الأعطال | Fault Recovery | عودة النظام إلى العمل ومعالجة الطلبات بعد الفشل |
| واجهة برمجة التطبيقات | API | عقدة الاتصال البرمجية بين المنصة والأنظمة الخارجية |
| رد النداء | Callback/Webhook | إرسال النتيجة تلقائيًا إلى النظام المصدر |
