# قائمة المصطلحات والاختصارات

> **حالة المراجعة:** تمت مراجعة المصطلحات الأساسية واعتمادها مبدئيًا بتاريخ 2026-07-22. يُحدّث هذا الملف عند اعتماد أي مصطلح جديد في المتطلبات أو التصميم.

| المصطلح | الاختصار / الاسم الإنجليزي | التعريف المعتمد في المشروع |
|---|---|---|
| نظام إدارة الطلبات عالية الحمل | HLRMS | المنصة الرئيسية التي تستقبل الطلبات وتدير معالجتها وتوفر حالتها ونتائجها |
| طلب | Request | وحدة عمل يرسلها نظام عميل إلى المنصة لمعالجتها |
| حمولة الطلب | Payload | البيانات الخاصة بالمهمة الموجودة داخل الطلب |
| معرّف الطلب | Request ID | معرّف فريد ينشئه النظام لتتبع الطلب |
| معرّف الارتباط | Correlation ID | معرّف يربط سجلات وخطوات الطلب عبر مكونات متعددة |
| مفتاح منع التكرار | Idempotency Key | قيمة تمنع تكرار الأثر عند إعادة إرسال الطلب نفسه |
| حالة الطلب | Request Status | المرحلة الحالية للطلب ضمن دورة حياته |
| أولوية الطلب | Priority | قيمة تساعد النظام على تفضيل بعض الطلبات في المعالجة |
| واجهة برمجة التطبيقات | API | عقد اتصال برمجي يحدد العمليات والبيانات المتبادلة بين المنصة والأنظمة العميلة |
| بوابة واجهات التطبيقات | API Gateway | نقطة دخول موحدة تستقبل طلبات العملاء وتطبق سياسات العبور الأساسية |
| وسيط الرسائل | Message Broker | نظام ينقل الرسائل بين المنتجين والمستهلكين |
| RabbitMQ | RabbitMQ | وسيط الرسائل المعتمد في المشروع لإدارة الطوابير وتسليم الرسائل |
| المنتج | Producer | مكون ينشر رسالة إلى وسيط الرسائل |
| المستهلك | Consumer | مكون يستقبل الرسائل من الطابور |
| وحدة التنفيذ | Worker | عملية أو خدمة تنفذ الطلبات المسحوبة من الطابور |
| مجموعة وحدات التنفيذ | Worker Pool | عدة Workers من النوع نفسه تعمل بالتوازي |
| الطابور | Queue | مخزن للرسائل المنتظرة للمعالجة |
| الطابور الدائم | Durable Queue | طابور يبقى تعريفه موجودًا بعد إعادة تشغيل RabbitMQ |
| المبادل | Exchange | مكون في RabbitMQ يوجه الرسائل إلى الطوابير |
| مفتاح التوجيه | Routing Key | قيمة تُستخدم لتحديد مسار الرسالة |
| الربط | Binding | قاعدة تربط Exchange بطابور |
| تأكيد المستهلك | ACK | إشعار بنجاح معالجة الرسالة وإمكانية حذفها من الطابور |
| رفض الرسالة | NACK | إشعار بفشل المعالجة مع إمكانية الإعادة أو التحويل |
| إعادة المحاولة | Retry | إعادة تنفيذ طلب فشل بسبب خطأ مؤقت |
| التراجع الزمني | Backoff | زيادة مدة الانتظار بين محاولات التنفيذ |
| طابور الرسائل الميتة | DLQ | طابور يستقبل الرسائل التي استنفدت محاولاتها أو رُفضت |
| مبادل الرسائل الميتة | DLX | Exchange يوجه الرسائل الفاشلة إلى DLQ |
| الجلب المسبق | Prefetch | عدد الرسائل غير المؤكدة المسموح بإرسالها لكل Consumer |
| مهلة التنفيذ | Timeout | الحد الزمني الأقصى المسموح به لتنفيذ عملية |
| التسليم مرة واحدة على الأقل | At-least-once Delivery | نمط تسليم قد يعيد الرسالة أكثر من مرة، ولذلك يتطلب معالجة آمنة ضد التكرار |
| المعالجة غير المتزامنة | Asynchronous Processing | قبول الطلب أولًا وتنفيذه لاحقًا دون إبقاء العميل منتظرًا |
| رد النداء | Callback / Webhook | طلب HTTP ترسله المنصة تلقائيًا إلى عنوان يحدده النظام العميل لإبلاغه بالنتيجة أو تغيّر الحالة |
| معدل المعالجة | Throughput | عدد الطلبات المنجزة خلال وحدة زمن |
| زمن الاستجابة | Response Time | الزمن بين إرسال الطلب واستلام الرد الأولي |
| زمن الانتظار | Queue Wait Time | الزمن بين دخول الرسالة إلى الطابور وبدء تنفيذها |
| زمن التنفيذ | Processing Time | الزمن الذي يستغرقه Worker لتنفيذ المهمة |
| الاختناق | Bottleneck | مكون يحد قدرة النظام الكلية |
| التوسع الأفقي | Horizontal Scaling | زيادة السعة بإضافة نسخ جديدة من الخدمة أو Worker |
| موازن الحمل | Load Balancer | يوزع الاتصالات على نسخ متعددة من الخدمة |
| تحديد المعدل | Rate Limiting | تقييد عدد الطلبات المسموح بها خلال مدة معينة |
| نقطة فحص الصحة | Health Check | واجهة تبين جاهزية الخدمة وحالتها التشغيلية |
| سجل النظام | Log | حدث نصي أو منظم يسجل ما جرى داخل أحد مكونات النظام |
| مقياس تشغيلي | Metric | قيمة رقمية تصف أداء النظام أو حالته |
| التتبع الموزع | Distributed Tracing | تتبع رحلة الطلب عبر مكونات متعددة |
| قابلية المراقبة | Observability | فهم حالة النظام باستخدام المقاييس والسجلات والتتبع |
| اختبار الحمل | Load Test | اختبار النظام تحت حمل متوقع ومتدرج |
| اختبار الضغط | Stress Test | رفع الحمل حتى تجاوز الحدود الطبيعية |
| اختبار الارتفاع المفاجئ | Spike Test | إرسال زيادة كبيرة ومفاجئة في الطلبات |
| التوفر العالي | High Availability | استمرار الخدمة رغم تعطل بعض المكونات |
| استعادة الأعطال | Fault Recovery | عودة النظام إلى العمل ومعالجة الطلبات بعد الفشل |
| اتفاقية مستوى الخدمة | SLA | مستوى الخدمة المستهدف من حيث التوفر أو زمن الاستجابة أو حدود أخرى |
