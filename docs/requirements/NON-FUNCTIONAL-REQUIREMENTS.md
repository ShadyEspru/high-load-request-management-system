# المتطلبات غير الوظيفية

## الاعتمادية والاتساق

| المعرّف | المتطلب | معيار التحقق |
|---|---|---|
| `NFR-001` | لا يفقد النظام طلبًا بعد نجاح القبول المتين | Accepted = Request = Outbox = Published = Processed بعد Recovery |
| `NFR-002` | تكون إعادة الطلب نفسه Idempotent ضمن المستخدم | Replay يعيد ID نفسه، والمحتوى المختلف يعيد 409 |
| `NFR-003` | تكون معالجة الرسالة آمنة مع At-Least-Once | Duplicate event لا ينفذ الأثر مرتين |
| `NFR-004` | يستعيد Outbox النشر بعد توقف RabbitMQ | Pending events تنشر بعد عودة Broker |
| `NFR-005` | لا تترك Retry المتعبة رسالة تدور بلا نهاية | يصبح الطلب FAILED وتنتقل الرسالة إلى DLQ |

## الأداء

| المعرّف | المتطلب | الحالة الحالية |
|---|---|---|
| `NFR-006` | يقاس معدل القبول بوضوح مع P95/P99 وFailures وDropped | منفذ بواسطة k6 وGrafana |
| `NFR-007` | يثبت Baseline محلي قابل للتكرار قبل Stress | Recorded Run عند 250 RPS، P95=628 ms |
| `NFR-008` | تصنف النتائج المتدهورة ولا تعرض كنجاح كامل | 350/500 وSoak موثقة بقيودها |
| `NFR-009` | يختبر 1000 RPS على Hostين منفصلين قبل اعتماده | Planned Validation؛ غير مثبت بعد |

لا يمثل رقم 1000 RPS متطلبًا ناجحًا حاليًا. يصبح نتيجة فقط بعد تنفيذ الاختبار وحفظ الأدلة الخام.

## القابلية للتوسع

| المعرّف | المتطلب | معيار التحقق |
|---|---|---|
| `NFR-010` | يمكن زيادة Worker Replicas دون تغيير منطق الطلب | تشغيل 1 و2 و4 و8 Workers |
| `NFR-011` | تبقى Correctness مستقلة عن عدد Workers | جميع 30001 رسالة عولجت في تجربة Scaling |
| `NFR-012` | لا يفترض التقرير Scaling خطيًا على موارد مشتركة | توثيق Speedup وEfficiency والقيود |

## الأمن

| المعرّف | المتطلب | معيار التحقق |
|---|---|---|
| `NFR-013` | تمر واجهات الطلبات عبر JWT صالح | 401 عند غياب الرمز أو عدم صلاحيته |
| `NFR-014` | لا يثق Request Service بترويسات عميل مباشرة | Gateway يحذف X-User-* ويعيد توليدها |
| `NFR-015` | يفصل USER عن ADMIN | 403 عند طلب Admin دون الدور المطلوب |
| `NFR-016` | لا تستخدم الأسرار الافتراضية في نشر فعلي | متغيرات بيئة وقيم قوية خارج المستودع |
